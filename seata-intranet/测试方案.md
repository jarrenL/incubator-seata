# Seata 2.5.0-GaussDB 内网环境测试方案

> **前提**：所有包已在外网预编译，内网解压即用，无需 Maven。

## 1. 交付物清单

内网机器上需要的全部文件：

```
seata-intranet/                       ← 配置 + 工具（拷到 ~/IdeaProjects/incubator-seata/）
├── env.sh                            ← 【唯一需要改的文件】GaussDB IP/端口/密码
├── SqlRunner.java / SqlRunner.class  ← JDBC 工具（已编译好）
├── gaussdbjdbc.jar                   ← GaussDB JDBC 驱动
├── init-db.sh                        ← 数据库初始化
├── check-data.sh                     ← 数据验证/重置
├── start.sh                          ← Seata Server 启动脚本（要拷到 seata-package/bin/）
└── 测试方案.md                       ← 本文件

/opt/seata-package/                   ← Seata Server 自包含包（解压自 tar.gz）
├── conf/application-gaussdb.yml
└── lib/*.jar  (218 个，含 JDBC 驱动)

/opt/seata-samples-package/           ← 样本应用自包含包（解压自 tar.gz）
├── bin/
│   ├── start-at.sh                   ← AT commit/rollback
│   ├── start-xa.sh                   ← XA 四服务
│   ├── start-tcc.sh                  ← TCC 全自动
│   ├── start-saga.sh                 ← Saga 全自动
│   └── kill-all.sh                   ← 清理所有端口
└── jars/{at,xa,tcc,saga}/            ← 全部 shaded，自包含
```

## 2. 部署（一次性）

```bash
# 1. 解压两个包
tar xzf seata-server-2.5.0-gaussdb.tar.gz -C /opt/
tar xzf seata-samples-package-2.5.0-gaussdb.tar.gz -C /opt/

# 2. 把 start.sh 拷入 Seata Server 包
cp ~/IdeaProjects/incubator-seata/seata-intranet/start.sh /opt/seata-package/bin/
chmod +x /opt/seata-package/bin/start.sh /opt/seata-samples-package/bin/*.sh

# 3. 改配置
cd ~/IdeaProjects/incubator-seata/seata-intranet
vim env.sh    # 改集中式/分布式的 IP 和密码
```

## 3. env.sh 配置说明

所有脚本执行前都必须 `source env.sh [centralized|distributed]`：

```bash
source env.sh centralized    # 集中式
source env.sh distributed    # 分布式
```

env.sh 会设置以下环境变量（脚本自动读取，无需手动传参）：

| 变量 | 用途 | 使用者 |
|------|------|--------|
| GAUSSDB_HOST/PORT/USER/PASSWORD | GaussDB 连接 | 所有脚本 |
| GAUSSDB_JDBC_BASE | JDBC URL 前缀 | start-at.sh, start-xa.sh |
| SEATA_STORE_DB_URL | Seata Server 元数据库 URL | start.sh |
| JDBC_JAR | GaussDB JDBC 驱动路径 | init-db.sh, check-data.sh |
| SEATA_PACKAGE_DIR | Seata Server 包路径（默认 /opt/seata-package） | start.sh |
| SAMPLES_PACKAGE_DIR | 样本包路径（默认 /opt/seata-samples-package） | 备选引用 |

## 4. 前置条件

### 4.1 环境检查

| 检查项 | 命令 | 预期 |
|--------|------|------|
| JDK 11+ | `java -version` | 11 或更高 |
| 包已解压 | `ls /opt/seata-package/lib/*.jar | wc -l` | >200 |
| 样本 jar | `ls /opt/seata-samples-package/jars/*/*.jar` | 8 个 jar |
| env.sh 已配置 | `source env.sh centralized && echo $GAUSSDB_HOST` | 内网 IP |
| 连通 GaussDB | `cd seata-intranet && source env.sh centralized && java -cp ".:$JDBC_JAR" SqlRunner "${GAUSSDB_JDBC_BASE}/postgres?currentSchema=public" "$GAUSSDB_USER" "$GAUSSDB_PASSWORD" - "SELECT 1"` | 输出 1 |

### 4.2 连通性测试

```bash
source env.sh centralized
java -cp ".:$JDBC_JAR" SqlRunner \
    "${GAUSSDB_JDBC_BASE}/postgres?currentSchema=public" \
    "$GAUSSDB_USER" "$GAUSSDB_PASSWORD" \
    - "SELECT 1"
# 预期输出: 1
```

## 5. 数据库初始化

```bash
source env.sh centralized   # 或 distributed
./init-db.sh all            # 一键完成：元数据表 + 业务库 + 种子数据
```

初始化的内容：

| 目标 | 内容 |
|------|------|
| postgres 库 | global_table, branch_table, lock_table, distributed_lock, vgroup_table（5张） |
| seata_account | account_tbl (U100001, money=10000) + undo_log |
| seata_order | order_tbl（空） + undo_log |
| seata_storage | stock_tbl (C00321, count=100) + undo_log |

### 分布式 GaussDB 额外步骤：修复 undo_log 序列

分布式版 SERIAL 自动创建的序列名带后缀（如 `undo_log_id_seq2100983941`），Seata 硬编码查找 `undo_log_id_seq`。每个库执行一次：

```sql
-- 查实际序列名
SELECT sequence_name FROM information_schema.sequences WHERE sequence_name LIKE 'undo_log%';

-- 删除 + 重建（GaussDB 分布式不支持 RENAME SEQUENCE）
DROP SEQUENCE IF EXISTS <实际序列名> CASCADE;
CREATE SEQUENCE undo_log_id_seq START 1;
ALTER TABLE undo_log ALTER COLUMN id SET DEFAULT nextval('undo_log_id_seq');
```

对 seata_account、seata_order、seata_storage 各执行一次。

## 6. 集中式 GaussDB 测试步骤

### 6.0 启动 Seata Server

```bash
source env.sh centralized
/opt/seata-package/bin/start.sh &
sleep 10
lsof -i :8091 | grep LISTEN   # 确认启动
```

### 6.1 AT 模式

```bash
source env.sh centralized
./check-data.sh reset

# commit
/opt/seata-samples-package/bin/start-at.sh commit
sleep 30
./check-data.sh

# rollback
./check-data.sh reset
/opt/seata-samples-package/bin/start-at.sh rollback
sleep 30
./check-data.sh
```

**commit 预期**：money=9600, order=1行(count=2), stock=98, undo_log 全为0
**rollback 预期**：money=10000, order=0, stock=100, undo_log 全为0

### 6.2 XA 模式

**前置条件**：`SHOW max_prepared_transactions` > 0。

```bash
source env.sh centralized
/opt/seata-samples-package/bin/start-xa.sh
curl http://127.0.0.1:7084/purchase/commit
sleep 5 && ./check-data.sh

./check-data.sh reset
curl http://127.0.0.1:7084/purchase/rollback
sleep 5 && ./check-data.sh
```

关键日志：`branch register success` → `XA START/END/PREPARE`
阻塞标志：`prepared transactions are disabled` → max_prepared_transactions=0

### 6.3 TCC 模式

TCC 不访问业务 GaussDB，无需 source env.sh。

```bash
/opt/seata-samples-package/bin/start-tcc.sh
# exit code 0 → ✅
```

期望日志：`commit status: Committed` + `rollback status: Rollbacked`

### 6.4 Saga 模式

```bash
/opt/seata-samples-package/bin/start-saga.sh
# 2 次 commit succeed + compensate → ✅
```

### 6.5 集中式测试结果

| 模式 | 结果 | 备注 |
|------|------|------|
| AT commit | ⬜ | money=9200, order=2, stock=96 |
| AT rollback | ⬜ | 数据不变 |
| XA commit | ⬜ | 需 max_prepared_transactions > 0 |
| XA rollback | ⬜ | 同上 |
| TCC | ⬜ | |
| Saga | ⬜ | |

## 7. 分布式 GaussDB 测试步骤

### 7.0 关键差异

| 差异点 | 集中式 | 分布式 | 影响 |
|--------|--------|--------|------|
| SERIAL 序列名 | `undo_log_id_seq` | `undo_log_id_seqXXXXXXXXXX` | AT 需修复序列（见 §5） |
| max_prepared_transactions | 单层 | CN/DN 分开 | XA 需所有 DN > 0 |
| TCC / Saga | — | — | 无差异（不访问业务 DB） |

### 7.1 切换并初始化

```bash
source env.sh distributed
./init-db.sh all
# ⚠️ 然后手动修复 undo_log 序列（见 §5）
```

### 7.2 AT 模式

```bash
source env.sh distributed
./check-data.sh reset

/opt/seata-samples-package/bin/start-at.sh commit
sleep 30 && ./check-data.sh

./check-data.sh reset
/opt/seata-samples-package/bin/start-at.sh rollback
sleep 30 && ./check-data.sh
```

预期同集中式（已验证 2026-05-12）。

### 7.3 XA 模式

**⚠️ CN 层 max_prepared_transactions=400 但 DN 可能=0，XA PREPARE 会被拒绝。**

```bash
source env.sh distributed
/opt/seata-samples-package/bin/start-xa.sh
curl http://127.0.0.1:7084/purchase/commit
```

### 7.4 TCC / Saga

与集中式完全相同：

```bash
/opt/seata-samples-package/bin/start-tcc.sh
/opt/seata-samples-package/bin/start-saga.sh
```

### 7.5 分布式测试结果

| 模式 | 结果 | 备注 |
|------|------|------|
| AT commit | ⬜ | 需修复 undo_log 序列 |
| AT rollback | ⬜ | 同上 |
| XA commit | ⬜ | 需 DN max_prepared_transactions > 0 |
| XA rollback | ⬜ | 同上 |
| TCC | ⬜ | 与集中式无差异 |
| Saga | ⬜ | 与集中式无差异 |

## 8. 故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `distributed_lock does not exist` | 元数据表未建 | `./init-db.sh server` |
| `undo_log_id_seq does not exist` | 分布式序列名不匹配 | 见 §5 |
| `prepared transactions are disabled` | max_prepared_transactions=0 | GaussDB 配置 + 重启 |
| `can not connect to [seata:8091]` | registry type 不是 file | 脚本已加 `--seata.registry.type=file` |
| `Connection refused` | env.sh 未 source 或 IP 配错 | `echo $GAUSSDB_HOST` 确认 |
| autocommit=false (XA) | 连接池状态残留 | 脚本已加 `hikari.auto-commit=true` |
| SqlRunner 找不到 | 未编译或路径错 | `ls seata-intranet/SqlRunner.class` |

### 一键重置

```bash
/opt/seata-samples-package/bin/kill-all.sh
source env.sh centralized && ./check-data.sh reset
/opt/seata-package/bin/start.sh &
sleep 10
```
